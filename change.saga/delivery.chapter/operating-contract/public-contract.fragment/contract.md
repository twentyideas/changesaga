# Open-source operating contract {#open-source-contract}

The public repository surface is part of delivery: the README supplies install and first-use paths; contributing guidance names local checks and format-change expectations; governance assigns decision and release responsibilities; security and support documents separate confidential vulnerabilities, ordinary bugs, and questions.[^public-contract]

Issue forms and the pull-request template ask reporters for reproducible evidence and contributors for test, compatibility, documentation, and security impact. Dependabot and read-only CI keep routine maintenance on the same visible path without granting forked code release credentials.[^repo-automation]

Design and operations notes preserve why the renderer behaves as a content-first review tool, how releases are cut, which performance budgets matter, and where deeper audits or future work live.[^documentation-map]

[^public-contract]: Repository-level policy files define installation, contribution, governance, conduct, security disclosure, support, licensing, and release history.
[^repo-automation]: GitHub templates and automation standardize evidence collection and run pull-request checks without crossing the release-signing boundary.
[^documentation-map]: The documentation index links renderer, release, performance, security-test, audit, and UX decisions as maintained engineering context.
